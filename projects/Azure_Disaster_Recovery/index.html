Azure Disaster Recovery

Create a Azure Disaster Recovery Demo with Backup and including RPO and RTO

Introduction

I wanted to explore the disaster recovery side of cybersecurity, what kind of things were expected, and what kind of technicalities did I have to learn.

Inital Blind Goals

Explore Disaster Recovery in Azure

Do Policy A, Do Policy B, Create a VM in Azure, Do the RPO matrix, Do the RTO, Do the backups, Document the process

Goals are usually vague because I don't know much about the subject or I'm trying to learn about something. So having a precise goal makes little sense because when I set up the goals, this was what I was imagining, what was needed from me in this kind of project. And then after that, the more I learned about the topic and the more I realized that there is more to it and more stuff to add in, but these were the initial goals.

Tools

Azure B2S VMs / Nginx for the app / Azure Backup / Azure Site Recovery for cross-vision.

Steps

Provisioning

I have a budget of $100 for the VM and all, so I had to be strategic. The first thing to do was put a budget in place.

Then I had to create the VM and I called it FinVM from like finance, I wanted to create like a fake company with like fake documentation and stuff for the RTO and RPO as well. So I needed a name and some departments, so I was, I didn't know how many VM I was going to create, I ended up doing just one, but I think one, I ended up calling it the FinVN for finance. Then I SSH inside the VM. So I chose the B2S series because it's a versatile and cheap alternative, like the D series is obviously better, but for a project of this size with a small budget, it was way easier to spin off and have it running early and it gives me more flexibility. I would have probably chose the B1S series, but it wasn't available, so...

So I had like one small issue that was a little bit notable is the SSH key too exposed on Windows that I never had this issue before. So this was interesting when trying to connect to the VM. It was a quick fix with by changing the permissions but I still think it was notable.

The App

After that, I created the app. So I just installed nginx. Created a small demo app. Nothing super complicated, but it needed to be done to simulate the app a company would use.

Allowed HTTP to see it on the internet (allowed for 10mn for testing)

Backup of VM

Then I started the backup process, so this is where everything a little bit more disaster recovery related starts. So I had to create the backup and then replicate them on another server, I mean on another region would be more precise.

Backup Policies

So then I created the backup policy. So these are supposed to be in relation with the RTO and RPO. And that's basically, I had to fix the, I kind of fixed some random numbers really, but I just did retention for 30 days. And yeah, if for the more critical stuff, I just increased the retention.

Site Recovery

So, I had multiple trouble when it came for the replication. So, the first one was there is an automatization account that is created automatically when it comes to replication, and it wouldn't let me create one because of the licensing. I have Azure student. So, I had to find a workaround with it, which was just create a Microsoft normal automatization account, not an automatic one created with the replication. Either way, once this was done, the replication still wouldn't go off because of the region. Again, the licensing only has access to certain regions, and I was initially wanting to go to Central because the Microsoft documentation was saying that the best between US East 2, the best replication you can do in terms of latency, I guess, would be with US Central, and I couldn't do that, so I ended up doing what I could do, which was South Central. Honestly, for the purpose of the demo, it doesn't change much. It's just that I had to find a workaround for every little problem, I guess.

Multiple things worth noting here. The first one was the GPU VM auto-assignment. It was more of a cost risk than a technical risk, but on small budgets it can make a difference, so it was something to adjust.
